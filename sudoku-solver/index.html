Digital Electronics Connection & Theoretical Mapping

Formal mapping between combinatorial digital logic elements and Sudoku constraint satisfaction problems.

⚠️
Important Academic Distinction: This project is a software implementation modelling digital logic concepts on a von Neumann processor using JavaScript. It mathematically models Boolean variables, logic gates, truth tables, and binary encoding rather than functioning as a physical hardware circuit built with physical TTL/CMOS ICs or FPGA silicon.
A

Binary Representation (4-Bit Register)

In digital systems, each decimal digit $1 \dots 9$ is encoded using a 4-bit binary word $(B_3 B_2 B_1 B_0)_2$, where $B_3$ is the Most Significant Bit (MSB, weight $2^3 = 8$) and $B_0$ is the Least Significant Bit (LSB, weight $2^0 = 1$).

B

Boolean Logic Modeling

Every candidate placement in Sudoku is governed by strict binary conditions. A condition can only take one of two discrete Boolean states:

  • Logic 1 (TRUE / HIGH): The condition is satisfied; no violation exists.
  • Logic 0 (FALSE / LOW): A conflict is detected; condition is violated.

We define three independent Boolean state variables for any candidate digit $D$ tested at coordinates $(r, c)$:

$$A = \text{ROW\_SAFE} \in \{0, 1\}$$ $$B = \text{COLUMN\_SAFE} \in \{0, 1\}$$ $$C = \text{BOX\_SAFE} \in \{0, 1\}$$

Each variable is evaluated independently through combinatorial inspection of the corresponding unit.

C

The 3-Input AND Gate Formulation

The fundamental constraint of Sudoku dictates that a candidate digit $D$ may only occupy a cell if and only if it satisfies all three orthogonal constraints concurrently.

In digital electronics, this exact behavior is implemented by a 3-Input AND Gate:

$$\text{VALID} = A \cdot B \cdot C = \text{ROW\_SAFE} \land \text{COLUMN\_SAFE} \land \text{BOX\_SAFE}$$

Operational Rule:

  • If all three inputs are Logic 1 ($A=1, B=1, C=1$), the gate outputs $\text{VALID} = 1$. The candidate is accepted and inserted into the board matrix.
  • If any single input drops to Logic 0, the AND gate output immediately collapses to $\text{VALID} = 0$. The candidate is rejected.
D

NOT Gate & Conflict Inversion

Physical identity comparators (such as 74LS85 ICs) naturally signal a match when a duplicate digit is found: $\text{CONFLICT} = 1$.

To convert a detected conflict into a "safe" condition suitable for the positive-logic AND gate, a NOT Gate (Inverter) is required:

$$\text{ROW\_SAFE} = \overline{\text{ROW\_CONFLICT}} = \text{NOT}(\text{ROW\_CONFLICT})$$ $$\text{COLUMN\_SAFE} = \overline{\text{COL\_CONFLICT}} = \text{NOT}(\text{COL\_CONFLICT})$$ $$\text{BOX\_SAFE} = \overline{\text{BOX\_CONFLICT}} = \text{NOT}(\text{BOX\_CONFLICT})$$

When a conflict occurs ($\text{CONFLICT}=1$), the inverter drives $\text{SAFE}=0$, which forces the 3-input AND gate to output $0$, automatically rejecting the candidate.

Algorithmic Architecture

Recursive Backtracking Algorithm

Depth-First Search (DFS) state space tree exploration with constraint pruning.

Step-by-Step Algorithm Execution

  1. Scan for Empty Cell: Inspect board for the next empty cell (value $= 0$) in row-major order $(r, c)$. If no empty cells remain, the puzzle is completely SOLVED.
  2. Iterate Candidate Digits: Test values $D \in \{1, 2, 3, 4, 5, 6, 7, 8, 9\}$ sequentially.
  3. Execute Digital Logic Validation: Compute Boolean safe signals: 
    rowSafe = isRowSafe(board, r, D);
colSafe = isColSafe(board, c, D);
boxSafe = isBoxSafe(board, r - (r % 3), c - (c % 3), D);
valid = rowSafe && colSafe && boxSafe;
  4. Tentative Insertion & Recursion: If $\text{valid} == 1$, assign $\text{board}[r][c] = D$ and recursively invoke solve(board).
  5. Backtracking Step: If the recursive call fails (returns false), reset cell $\text{board}[r][c] = 0$ (backtrack) and attempt the next candidate $D+1$.
  6. Exhaustion: If all digits $1\dots 9$ fail at the current cell, return false to the previous recursion frame. If the root frame fails, the puzzle is UNSOLVABLE.

Complexity Analysis

Time Complexity: Worst-Case $\mathcal{O}(9^m)$

Where $m \le 81$ is the number of unassigned cells. In the worst theoretical case without constraints, each cell could try 9 numbers. In practice, constraint pruning (evaluating $A \cdot B \cdot C$) eliminates vast branches of the state-space tree, allowing 99% of valid puzzles to solve in under 15 milliseconds.

Space Complexity: $\mathcal{O}(m)$

The call stack depth is strictly bounded by the number of empty cells $m \le 81$. The board matrix occupies constant memory $\mathcal{O}(81) = \mathcal{O}(1)$ of 81 4-bit nibbles.

Pruning Efficiency

By enforcing $A \cdot B \cdot C$ prior to recursing, invalid branches are pruned at depth $d=0$ or $d=1$, preventing exponential explosion.
